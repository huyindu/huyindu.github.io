Claude Code 开发实战指南：Superpowers + GStack 插件安装与常用命令

Claude Code 是 Anthropic 推出的终端原生 AI 编程助手，它不是一个 IDE 插件，而是一个直接运行在终端里的智能代理——能读代码、写代码、执行命令、操作 Git、运行测试，甚至能操作浏览器进行端到端验证。2026 年，围绕 Claude Code 已经形成了一个成熟的插件生态，其中最核心的两个工具是 Superpowers 和 GStack。

本文将从零开始，带你完成 Claude Code 的安装配置，并深入讲解 Superpowers 和 GStack 两大插件的使用方法。

一、Claude Code 安装

1.1 前置要求

项目 要求
操作系统 macOS 13+ / Linux / Windows 10+
账号 Claude Pro ($20/月)、Max ($100-200/月) 或 Team/Enterprise
内存 4 GB 起步，8 GB 推荐
终端 Bash / Zsh / PowerShell / CMD
Git 需要（用于代码变更追踪和版本管理）

1.2 安装方式

方式一：原生安装器（2026 年推荐）

原生安装器不需要 Node.js，自带自动更新，是目前官方推荐的安装方式。

# macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell（安装后需将 %USERPROFILE%\.local\bin 加入 PATH）
irm https://claude.ai/install.ps1 | iex

方式二：Homebrew（macOS/Linux）

brew install --cask claude-code

方式三：WinGet（Windows）

winget install Anthropic.ClaudeCode

方式四：npm 安装（兼容路径）

需要 Node.js 18+。虽然 2026 年起官方推荐原生安装器，但 npm 方式在 CI/CD 流水线、版本锁定、标准化 Node.js 开发环境中仍然实用。

npm install -g @anthropic-ai/claude-code

# 验证
claude --version

注意：不要使用 sudo npm install -g，会导致文件权限问题。如果之前用 npm 安装过，可以运行 claude install 迁移到原生安装器（保留所有配置），然后 npm uninstall -g @anthropic-ai/claude-code 清理旧包。

1.3 VS Code 扩展安装

Claude Code 也提供了 VS Code 官方扩展，让你在编辑器内直接使用 Claude Code，无需切换终端。

前提条件：

  • VS Code 版本 ≥ 1.98.0
  • 已安装 Claude Code CLI（按上面的方式任选一种）

安装步骤：

  1. 打开 VS Code，按 Ctrl+Shift+X（Windows/Linux）或 Cmd+Shift+X（Mac）打开扩展面板
  2. 搜索 "Claude Code"，选择发行商为 Anthropic 的官方扩展
  3. 点击 Install 安装

或者用命令行一键安装：

code --install-extension anthropic.claude-code

使用方法：

入口 操作 适用场景
⚡ Spark 图标 点击编辑器右上角闪电图标 快速提问当前文件
状态栏 点击底部右下角 ✱ Claude Code 无需打开文件也能对话
命令面板 Cmd+Shift+P → "Claude Code: Open in New Tab" 独立对话窗口

提示：如果安装后 Spark 图标不显示，打开一个文件（仅打开文件夹不够），确认 VS Code ≥ 1.98.0，然后运行 Developer: Reload Window 刷新窗口。

1.4 验证安装与认证

# 验证安装
claude --version

# 健康检查
claude doctor

# 启动 Claude Code（首次运行会打开浏览器进行 OAuth 认证）
cd /path/to/your/project
claude

启动后，在 Claude Code 交互终端中运行 /init 命令，它会自动分析项目结构并生成 CLAUDE.md 文件。这个文件是 Claude Code 理解你项目的"说明书"，质量越高，AI 的输出越精准。

二、Superpowers 插件

Superpowers（GitHub: obra/superpowers，⭐ 149K+）由 Jesse Vincent 创建，核心理念是 "Process over Prompt"（流程大于提示词）。它不是让 AI 变聪明，而是强制 AI 遵循软件工程最佳实践：先想清楚再动手、先写测试再写代码、每个任务独立审查。

2.1 安装 Superpowers

方式一：通过 Claude Code 插件市场（推荐）

# 在 Claude Code 会话中执行
/plugin install superpowers@claude-plugins-official

方式二：通过 Superpowers 自有市场

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

方式三：npm 全局安装（跨工具）

npm install -g superpowers-openspec-team
sot init /path/to/your/project --tool claude-code

2.2 验证安装

重启 Claude Code 后，随便提一个开发需求（比如"帮我做一个用户登录功能"），如果 AI 先进入提问模式而不是直接写代码，说明 Superpowers 已生效。

你也可以用以下命令确认：

/superpowers:brainstorm

2.3 核心技能一览

技能 命令 作用
需求细化 /superpowers:brainstorming 编码前的苏格拉底式提问，理清边界与约束
制定计划 /superpowers:writing-plans 生成详细实现计划，精确到文件路径
执行计划 /superpowers:executing-plans 按计划批量执行，支持人类检查点
TDD 开发 自动触发 红-绿-重构循环，强制先写失败测试再写代码
系统化调试 /superpowers:systematic-debugging 4 阶段调试：现象→假设→实验→验证
并行子代理 /superpowers:dispatching-parallel-agents 多子 Agent 并行执行独立任务
子代理开发 /superpowers:subagent-driven-development 每任务派发干净上下文子代理，双阶段审查
代码审查 /superpowers:requesting-code-review 多维度审查（Critical/Warning/Info）
Git Worktree /superpowers:using-git-worktrees 隔离 Git Worktree 环境，并行开发互不干扰
分支收尾 /superpowers:finishing-a-development-branch 完成后自动跑测试、生成 Review 总结
完成验证 /superpowers:verification-before-completion 任务完成前强制验证，确保功能可用
自定义技能 /superpowers:writing-skills 创建团队专属技能文件（元技能）

2.4 标准开发流程

使用 Superpowers 后，你的开发流程会从"随口一说就开始写"变成这样：

  1. brainstorming → AI 通过提问理清需求、边界、技术约束
  2. writing-plans → 生成实现计划：文件列表、依赖关系、任务拆分
  3. 人工审阅计划 → 在你的确认之前 AI 不会动手写代码
  4. executing-plans → 自动分发给子 Agent，每个 Agent 严格遵循 TDD
  5. verification + code review → 自动跑测试 + 最终审查
  6. finishing-a-development-branch → 清理收尾

简单任务（改文案、修 typo）可以跳过完整流程，但功能开发和 Bug 修复建议严格遵循。

三、GStack 插件

GStack（GitHub: garrytan/gstack，⭐ 71K+）由 Y Combinator CEO Garry Tan 创建。如果 Superpowers 是"大脑"（管你怎么想），GStack 就是"双手"（管你怎么干）。它把 Claude Code 变成一个包含 23+ 角色的虚拟工程团队：有 CEO 做产品评审、有设计师做 UI 审查、有 QA 做浏览器测试、有运维做部署发布。

3.1 安装 GStack

GStack 依赖 Bun（推荐）或 Node.js，请先确保已安装。

# 全局安装（推荐，所有项目可用）
git clone https://github.com/garrytan/gstack.git ~/.claude/skills/gstack
cd ~/.claude/skills/gstack
./setup

安装完成后重启 Claude Code，GStack 的 23+ 个斜杠命令会自动生效。

3.2 升级 GStack

# 方法一：命令行升级
cd ~/.claude/skills/gstack
git fetch origin && git reset --hard origin/main && bash ./setup

# 方法二：内置命令升级
/gstack-upgrade

3.3 核心命令速览

产品与规划

命令 角色 用途
/office-hours 产品头脑风暴 在写代码前重新审视想法，YC 风格的产品验证
/plan-ceo-review CEO / 产品战略 战略审查、需求优先级排序
/plan-eng-review 工程经理 架构审查、数据流、测试策略
/plan-design-review 设计评审 UI/UX 评分（0-10）与优化建议

开发与审查

命令 角色 用途

浏览器与测试

四、Claude Code 常用内置命令

除了插件提供的命令，Claude Code 自身也内置了大量实用命令。

4.1 会话管理

命令 作用
/clear 清空对话历史，重新开始
/compact 智能压缩上下文（保留关键信息，释放 token）
/resume 恢复之前的会话
/rename 给当前会话命名
/branch 分叉会话（探索替代方案而不丢失当前状态）
/export 导出对话历史
/recap 一句话会话摘要，快速恢复上下文

4.2 上下文与成本

命令 作用
/context 查看上下文窗口使用情况（系统提示、文件、历史等详细分布）
/cost 查看当前会话的 token 消耗和费用
/status 完整会话状态 + 上下文使用百分比
/usage 账户级别配额使用情况

4.3 模式与模型

命令 作用
/model 切换模型（Sonnet / Opus / Haiku）
/effort 设置推理深度：low / medium / high / xhigh / max / auto
/plan 进入规划模式（只读探索，不修改文件）
/execute 退出规划模式，开始执行修改
/fast 切换高速模式（约 2.5x 速度，成本更高）
/sandbox 启用 OS 级沙箱隔离（文件系统 + 网络 + 进程）

4.4 开发与自动化

命令 作用
/init 初始化项目 CLAUDE.md 文件
/diff 交互式查看未提交的代码变更
/commit 暂存并提交，自动生成 commit 信息
/review 对当前变更进行代码审查
/security-review 扫描未提交变更中的安全漏洞
/batch 大规模并行重构（派发 5-30 个子 Agent）
/loop 定时重复执行（如 /loop 5m check deploy）
/tasks 监控后台任务和子 Agent
/debug 启动调试日志并分析

4.5 配置与环境

命令 作用
/config 打开设置界面（主题、模型、输出风格）
/permissions 管理工具和文件权限
/add-dir 添加额外工作目录
/plugin 安装/管理插件
/skills 查看和搜索已安装的技能
/mcp 管理 MCP 服务器连接
/hooks 管理事件钩子
/doctor 系统健康检查和依赖验证
/feedback 提交 bug 报告或反馈

五、Superpowers + GStack 协同工作流

这两个工具不是竞品，而是互补关系。Superpowers 管"怎么想"，GStack 管"怎么干"。推荐的协同方式如下：

[需求]
  ↓ /superpowers:brainstorming     ← "该不该做？怎么做最合理？"
  ↓ /superpowers:writing-plans      ← "具体方案是什么？"
  ↓ /office-hours                   ← "从产品视角再审视一遍"
  ↓ /plan-ceo-review                ← "战略对齐了吗？"
  ↓ /plan-eng-review                ← "架构合理吗？"
  ↓ /superpowers:executing-plans    ← "按计划实现（TDD + 子代理）"
  ↓ /qa  或  /browse                ← "浏览器真实验证"
  ↓ /superpowers:requesting-code-review ← "独立审查通道"
  ↓ /review                         ← "偏执级最终检查"
  ↓ /ship                           ← "一键发布"
  ↓ /land-and-deploy                ← "合并 + CI + 部署验证"
[上线]

实际使用中，你不需要每次都跑完全流程。可以根据任务复杂度灵活调整：

  • 简单修改（修 typo、改样式）：直接改，用 /review 快速检查即可
  • 中等功能（新增 API、重构模块）：brainstorming → writing-plans → 实现 → review → ship
  • 大型功能（新系统、架构变更）：跑完整流程，加上 /autoplan 串联审查

六、实用技巧

6.1 项目级安装 GStack（团队共享）

如果想让整个团队都使用 GStack，可以把插件文件提交到项目仓库：

cp -Rf ~/.claude/skills/gstack .claude/skills/gstack
rm -rf .claude/skills/gstack/.git
cd .claude/skills/gstack
./setup

这样其他团队成员 clone 项目后就能直接使用 GStack 命令。

6.2 自定义斜杠命令

Claude Code 支持创建自定义命令，放在两个位置：

  • 项目级：.claude/commands/（提交到 Git，团队共享）
  • 全局：~/.claude/commands/（个人使用，所有项目可用）

例如创建 .claude/commands/deploy.md：

部署应用到 $ARGUMENTS 环境。
1. 运行测试：npm test
2. 构建：npm run build
3. 部署：npm run deploy:$ARGUMENTS
4. 验证健康检查端点
5. 报告成功或在健康检查失败时回滚

使用：/deploy staging 或 /deploy production

$ARGUMENTS 会捕获命令后面输入的所有参数。

6.3 上下文管理

长会话的上下文窗口会逐渐占满，影响 AI 输出质量。几个实用技巧：

  • 用 /compact 而不是 /clear——compact 会保留关键决策和文件信息，比清空重来高效得多
  • 定期用 /context 查看上下文占用情况
  • 用 /cost 监控 token 消耗，避免意外超支
  • 复杂任务开启前先 /plan，在规划模式下免费探索代码库

6.4 安全开发

  • 不确定的操作用 /plan 模式先探索，确认后再 /execute
  • 高风险目录用 /freeze <dir> 限制编辑范围
  • 上线前用 /cso 做安全审计，/security-review 扫描未提交变更
  • Git 操作前确保有可回滚状态，善用 /branch 分叉探索

总结

Claude Code 在 2026 年已经从"终端里的聊天机器人"进化为完整的 AI 开发平台。核心公式很简单：

Claude Code（基座）+ Superpowers（纪律） + GStack（团队） = AI 驱动的完整工程组织

Superpowers 确保你不会写出烂代码，GStack 确保你不会漏掉产品审查、测试、部署任何一个环节。二者叠加，能把一个独立开发者的产出提升到小团队的水平。

安装顺序建议：先装 Claude Code → 跑 /init → 装 Superpowers → 装 GStack → 从一个小功能开始，按完整流程走一遍。踩过一遍完整流程后，你就能根据任务复杂度灵活裁剪工作流了。
