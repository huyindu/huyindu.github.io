Hermes Agent 安装配置指南：接入 DeepSeek API 和飞书

Hermes Agent 是 Nous Research 开源的一款终端原生 AI 代理框架，和 Claude Code、OpenAI Codex 属于同一类别——运行在终端中，通过工具调用与系统交互，能读写文件、执行命令、操作 Git、搜索网页，甚至调度子代理并行工作。不同的是，Hermes 完全不绑定任何模型供应商：你可以用 DeepSeek、Anthropic、OpenAI、OpenRouter，或者跑本地模型，同一个 Agent 切换模型不需要改动任何代码。

本文基于本机实际部署环境（Debian 12，Hermes v0.15.1，DeepSeek V4 Pro，飞书 WebSocket 连接），从安装到生产可用，把每一步的命令和踩坑点都写清楚。

一、Hermes Agent 是什么

先把几个关键特性列清楚，有个全局认知：

特性 说明
终端原生 直接在 Bash/Zsh 里运行，支持交互式和单次查询两种模式
模型无关 支持 20+ 模型供应商，通过 hermes model 随时切换
多平台网关 同一个 Agent 可通过 Telegram、Discord、飞书、Slack、微信等 15+ 平台交互
自学习技能 完成任务后能把工作流保存为「技能」(Skill)，下次自动加载复用
持久记忆 跨会话记住用户偏好、环境细节、项目约定
子代理调度 通过 delegate_task 并行派发子任务到独立 Worker
定时任务 内置 Cron 调度器，支持按表达式或自然语言安排周期任务
多配置文件 Profile 机制支持多套独立配置（不同项目、不同模型）

二、安装 Hermes

2.1 前置要求

项目 要求
操作系统 Linux / macOS / Windows (WSL)
Python 3.11+
Git 2.30+
网络 需访问 GitHub 和 DeepSeek API（国内需代理）

国内网络提醒：DeepSeek API 国内可直接访问，但 GitHub 和 PyPI 可能需要代理或镜像。如果遇到下载慢的情况，可以设置 pip 清华镜像：pip install -i https://pypi.tuna.tsinghua.edu.cn/simple <package>，或配置 HTTP 代理：export ALL_PROXY=socks5h://127.0.0.1:10808。

2.2 方式一：一键安装脚本（推荐）

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

脚本会自动完成：创建虚拟环境、安装依赖、配置 PATH。安装完成后验证：

hermes --version
# 输出: Hermes Agent v0.15.1

2.3 方式二：从源码安装

如果你需要修改源码或使用开发中的特性，可以从 GitHub 克隆：

git clone https://github.com/NousResearch/hermes-agent.git ~/hermes-agent
cd ~/hermes-agent
python -m venv venv
source venv/bin/activate
pip install -e .

# 添加到 PATH
ln -s ~/hermes-agent/venv/bin/hermes ~/.local/bin/hermes

本机实际部署用的就是源码安装方式，方便随时 git pull 更新。

2.4 初始化配置

安装完成后运行配置向导：

hermes setup

这会交互式引导你完成模型、终端、网关等核心配置。配置文件存放位置：

文件 路径 用途
主配置 ~/.hermes/config.yaml 模型、工具、代理行为等所有设置
环境变量 ~/.hermes/.env API Key、密钥等敏感信息
技能目录 ~/.hermes/skills/ 已安装的技能文件
会话存储 ~/.hermes/state.db SQLite 会话历史（FTS5 全文索引）

三、接入 DeepSeek API

DeepSeek 是目前性价比最高的 API 之一，国内直接访问，延迟低。Hermes 原生支持 DeepSeek provider，配置只需要两步。

3.1 获取 API Key

访问 platform.deepseek.com/api_keys 创建 API Key。新用户注册一般有免费额度。

3.2 配置 API Key

编辑 ~/.hermes/.env，添加：

DEEPSEEK_API_KEY=sk-xxx...

也可以用 hermes auth add deepseek 交互式输入。

3.3 配置模型

编辑 ~/.hermes/config.yaml，设置 model 段：

model:
  default: deepseek-v4-pro       # 默认模型
  provider: deepseek             # 供应商
  base_url: https://api.deepseek.com/v1  # API 地址

也可以用交互式命令切换：

hermes model    # 打开模型选择器，选 deepseek → deepseek-v4-pro

3.4 验证

hermes chat -q "简单介绍一下你自己"
# 应该收到 DeepSeek 模型的回复

如果想临时覆盖模型（不修改默认配置）：

hermes chat -q "..." -m deepseek-v4-pro --provider deepseek

3.5 支持的其他 DeepSeek 模型

模型 特点
deepseek-v4-pro 最新旗舰，综合能力最强
deepseek-chat V3 系列，高性价比通用模型
deepseek-reasoner R1 系列，深度推理

四、接入飞书

Hermes 的 Gateway 模块支持 15+ 消息平台，包括飞书。接入后可以直接在飞书群里 @机器人 发指令，Hermes 会在终端执行并返回结果。

4.1 创建飞书应用

  1. 打开 飞书开放平台
  2. 创建企业自建应用，填写应用名称和描述
  3. 在「添加应用能力」中添加「机器人」
  4. 在「权限管理」中搜索并开启以下权限：
    • im:message — 获取与发送消息
    • im:message.group_at_msg — 读取群 @ 消息
    • im:message.p2p_msg — 读取单聊消息
    • im:resource — 获取消息中的文件资源
  5. 在「安全设置」中配置 IP 白名单（或留空允许所有 IP）
  6. 发布应用，等待管理员审批

4.2 获取凭证

在飞书开放平台「凭证与基础信息」页面，复制以下信息：

  • App ID — 应用唯一标识
  • App Secret — 应用密钥（只显示一次，复制后妥善保存）

4.3 安装 lark-oapi SDK

飞书适配器依赖 lark-oapi。进入 Hermes 的虚拟环境安装：

# 源码安装的：激活 venv
source ~/hermes-agent/venv/bin/activate
pip install lark-oapi

# 如果用的 PyPI 清华镜像
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple lark-oapi

安装完成后验证：

python -c "import lark_oapi; print('OK')"

4.4 配置环境变量

编辑 ~/.hermes/.env，添加以下配置：

# 飞书应用凭证（必填）
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=你的AppSecret

# 飞书环境类型
FEISHU_DOMAIN=feishu            # 飞书用 feishu，Lark 国际版用 lark

# 连接方式
FEISHU_CONNECTION_MODE=websocket  # WebSocket 长连接，推荐

# 权限控制
FEISHU_ALLOW_ALL_USERS=true     # true: 允许所有用户，false: 只允许白名单
FEISHU_ALLOWED_USERS=           # 白名单用户 ID（逗号分隔），为空表示不限制
FEISHU_GROUP_POLICY=open        # 群聊策略: open(任何人可加群) 或 private(仅群主可加)

踩坑记录：本机初次部署时，Gateway 日志报 lark-oapi not installed or FEISHU_APP_ID/SECRET not set。原因是只在系统 Python 环境装了 lark-oapi，而 Hermes 的 systemd 服务运行在它自己的 venv 里。解决方法：激活 Hermes 的 venv 再装 lark-oapi，或者用 sudo hermes gateway restart --system 之前确认 which python 指向正确的 venv。

4.5 启动 Gateway

# 前台运行（测试用）
hermes gateway run

# 安装为系统服务（生产用，开机自启）
sudo hermes gateway install
sudo systemctl status hermes-gateway

# 管理服务
sudo hermes gateway restart
sudo hermes gateway stop
sudo hermes gateway status

服务启动后，日志位置：

grep -i "feishu\|error" ~/.hermes/logs/gateway.log | tail -20

4.6 在飞书中使用

Gateway 启动成功后：

  • 单聊：在飞书中直接搜索你的应用名称，开始对话
  • 群聊：把应用添加到群组，@机器人 + 消息即可触发
  • 安全机制：终端执行的命令会先推送到飞书等待审批（Gateway 模式下默认 approvals.mode: manual）

飞书中支持的常用交互：

  • /approve — 审批待执行的命令
  • /deny — 拒绝待执行的命令
  • /sethome — 将当前聊天设为主频道
  • /restart — 重启 Gateway
  • /status — 查看会话信息
  • /model [name] — 查看或切换模型
  • /config — 查看当前配置

提示：如果 Gateway 在 SSH 断开后停止，需要启用 systemd linger：sudo loginctl enable-linger $USER。

八、常见问题

Q: Gateway 启动后飞书没反应？

检查三步：

  1. hermes gateway status 确认服务正在运行
  2. grep -i feishu ~/.hermes/logs/gateway.log | tail -20 查看飞书连接日志
  3. 确认 lark-oapi 已安装：python -c "import lark_oapi"

Q: DeepSeek API 返回 401？

检查 ~/.hermes/.env 中 DEEPSEEK_API_KEY 是否正确。注意不要有多余的引号或空格。可以用 hermes doctor 诊断。

Q: 工具或技能修改不生效？

工具和技能在会话启动时加载，修改后需要 /reset 开始新会话。Gateway 模式下用 /restart 重启。

Q: SSH 断开后 Gateway 停止？

需要 enable linger：sudo loginctl enable-linger $USER，然后用 sudo hermes gateway install 安装为系统服务。

Q: 如何用本地模型替代 DeepSeek？

Hermes 支持通过 llama.cpp、vLLM 等运行本地模型。配置 model.provider: custom 并设置 model.base_url 指向本地推理服务。

九、总结

Hermes Agent 的核心优势在于灵活性和可扩展性：不锁定任何模型供应商，支持 15+ 消息平台，自带技能系统和持久记忆。对于国内开发者，配合 DeepSeek API（国内直连、低延迟、高性价比）和飞书（日常协作工具），可以构建一个真正融入工作流的 AI 助手。

安装路径回顾：

  1. curl ... | bash 一键安装 Hermes
  2. 配置 DEEPSEEK_API_KEY + model.provider: deepseek
  3. 创建飞书应用 → 安装 lark-oapi → 配置 FEISHU_* 环境变量
  4. sudo hermes gateway install 让 Gateway 开机自启
