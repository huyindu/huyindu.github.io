.NET Core 2.1 + Vue CLI 全栈项目搭建

为什么会走到前后端分离

2018 年初我手上维护的那个 ASP.NET MVC 项目，前端业务逻辑全搅在 Razor 视图和 jQuery 里，一个页面可能有 800 行的 $(function(){ ... })，改一个表单字段要在三个 cshtml 之间来回跳。正好 .NET Core 2.1 Preview 发布，带上了 SignalR 和 Razor Class Libraries，公司决定新项目用前后端分离的模式重写。

选 Vue 没选 React 的原因很实际：Vue 的中文文档质量高，团队里后端转前端的同事上手快。Vue CLI 3.0-rc 刚出，webpack 配置全部收敛到 vue.config.js，比以前手改 webpack.config 舒服得多。

后端：.NET Core 2.1 Web API 骨架

用 dotnet new webapi 初始化项目，出来的控制器默认是 [Route("api/[controller]")] 风格。保留 Controller 只做路由和参数校验，业务逻辑全抽到 Service 层。

dotnet new webapi -n MyApp.Api --no-https
cd MyApp.Api
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.AspNetCore.Cors

Startup.cs 里需要配 CORS，开发阶段前端跑在 localhost:8080，后端在 localhost:5000，跨域是绕不开的。我推荐用命名策略而不是通配 *：

// Startup.cs ConfigureServices
services.AddCors(options =>
{
    options.AddPolicy("Dev", builder =>
        builder.WithOrigins("http://localhost:8080")
               .AllowAnyHeader()
               .AllowAnyMethod());
});

// Configure
app.UseCors("Dev");

JSON 序列化默认是 camelCase，Vue 前端返回的字段也是驼峰——这点刚好对齐。但如果数据库字段用 PascalCase（传统 .NET 习惯），可以在 AddMvc() 里配置：

services.AddMvc()
    .AddJsonOptions(opt =>
    {
        opt.SerializerSettings.ContractResolver =
            new CamelCasePropertyNamesContractResolver();
    });

前端：Vue CLI 3.0-rc 的项目初始化

Vue CLI 3 的核心变化是 vue create 替代 vue init webpack，交互式选择 Babel、Router、Vuex、CSS pre-processor 等插件。我习惯勾上 Vue Router + Vuex + SCSS，开箱即用。

npm install -g @vue/cli@3.0.0-rc.5
vue create myapp-client
cd myapp-client
vue add axios

项目结构出来大概是 src/views/ 放页面级组件、src/components/ 放可复用组件、src/store/ 放 Vuex modules、src/api/ 统一放 axios 请求封装。

开发代理是前后端分离的第一步关键配置。在项目根目录加 vue.config.js：

module.exports = {
  devServer: {
    port: 8080,
    proxy: {
      '/api': {
        target: 'http://localhost:5000',
        changeOrigin: true
      }
    }
  }
};

这样前端所有 /api/* 请求会被 dev server 转发到 .NET Core 后端，不需要后端配 CORS。但 proxy 只解决开发环境问题——生产环境你仍然需要 CORS 或者 nginx 反代把前后端放在同一个域下。

axios 封装和 token 管理

统一封装 axios instance 是必定要做的。加 request interceptor 注入 token，加 response interceptor 统一处理 401：

// src/api/http.js
import axios from 'axios';
import router from '@/router';

const service = axios.create({
  baseURL: '/api',
  timeout: 15000
});

service.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

service.interceptors.response.use(
  response => response.data,
  error => {
    if (error.response && error.response.status === 401) {
      localStorage.removeItem('token');
      router.push('/login');
    }
    return Promise.reject(error);
  }
);

export default service;

Vuex 里按模块拆分，每个 domain 一个 module 文件。store 不应该直接调 axios，而是通过 src/api/ 下的方法间接调用——这样单元测试 mock 更干净。

JWT 认证的来回

.NET Core 2.1 内置 JWT 支持不需要额外装包。在 ConfigureServices 里配置认证：

services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = Configuration["Jwt:Issuer"],
            ValidAudience = Configuration["Jwt:Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(Configuration["Jwt:Key"]))
        };
    });

Controller 上加 [Authorize] 即可。登录接口返回的 token 格式：

var claims = new[]
{
    new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
    new Claim(ClaimTypes.Name, user.UserName),
    new Claim(ClaimTypes.Role, user.Role)
};

var key = new SymmetricSecurityKey(
    Encoding.UTF8.GetBytes(_config["Jwt:Key"]));
var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

var token = new JwtSecurityToken(
    issuer: _config["Jwt:Issuer"],
    audience: _config["Jwt:Audience"],
    claims: claims,
    expires: DateTime.Now.AddHours(8),
    signingCredentials: creds);

return Ok(new { token = new JwtSecurityTokenHandler().WriteToken(token) });

前端收到 token 存 localStorage，axios interceptor 自动带上。需要注意的是 token 过期后的处理：我碰见过好几次接口突然报 401，排查发现是前后端时间有偏差导致 token 提前失效。生产环境走 NTP 对时可以避免。

联调和发布

开发阶段前端 npm run serve + 后端 dotnet run 并行工作。联调问题时通常先看 Network 面板确认请求到底发出了没、状态码是什么。

生产发布有两种选择。方案 A：前端 npm run build 产出 dist/，后端用 app.UseStaticFiles() 直接 serve 这些静态文件，适合简单部署。方案 B：前端单独部署到 nginx 或 CDN，适合流量大、需要独立扩容的场景。我项目体量不大，用了方案 A：

app.UseStaticFiles();
app.UseMvc(routes =>
{
    routes.MapSpaFallbackRoute("spa-fallback",
        new { controller = "Home", action = "Index" });
});

把所有非 API 请求 fallback 到 index.html，Vue Router 的 HTML5 History 模式就能正常工作。

从传统 ASP.NET 跳到 .NET Core + Vue 前后端分离，初期配环境确实多花了两天时间，但代码结构清晰了不是一点半点。后端专注数据，前端专注 UI，接口约定好之后两边几乎不用相互等——这在之前混在一起的 Razor 项目里是不可想象的。
